# 3.9. Aspectos que se deben controlar para garantizar la calidad

Para mí, Freenglish tiene calidad si cumple sus requisitos, no falla en lo importante, se entiende sin ayuda, protege los datos de los alumnos y, sobre todo, si el contenido que enseña es correcto. Para cada aspecto definí un criterio que se pueda comprobar. Los indicadores concretos y cómo los mido durante el proyecto los detallo en el apartado 5.2.


CUMPLIMIENTO DE REQUISITOS

Criterio: el 100 % de los requisitos imprescindibles del apartado 2.6 están implementados y tienen al menos una prueba que los comprueba. La relación entre requisito, funcionalidad y prueba la llevo en una matriz de trazabilidad (apartado 5.7).


FUNCIONAMIENTO CORRECTO Y AUSENCIA DE ERRORES GRAVES

- La lógica del curso (corrección de ejercicios, avance por dominio, cajas de Leitner y sincronización) tiene pruebas unitarias, como hacemos en clase con los ViewModel y los casos de uso, y todas pasan antes de cada versión.
- La API tiene pruebas de cada endpoint, incluidos los casos de error.
- Al entregar no queda abierto ningún error grave, es decir, ninguno que haga perder progreso, cierre la app o impida avanzar en el curso.


CALIDAD DEL CONTENIDO

Es el aspecto más importante, porque un error en un curso de idiomas se aprende como si fuera correcto.
- Cada unidad pasa una lista de revisión antes de publicarse: ortografía y gramática del inglés y del español, que los ejercicios tengan una sola respuesta correcta, que las explicaciones de los errores sean claras y que cada imagen tenga su licencia registrada.
- El vocabulario y la gramática de cada unidad corresponden al nivel A1 o A2 según los descriptores del MCER.


USABILIDAD

- Una persona que no conoce la app puede completar la prueba de nivel y la primera lección sin ayuda.
- Lo compruebo en las pruebas con usuarios, observando dónde se atascan y con un cuestionario de satisfacción.


ACCESIBILIDAD

- En Android, la app no muestra problemas graves en Accessibility Scanner de Google.
- En la web, la puntuación de accesibilidad de Lighthouse es de 90 o más.
- Contraste suficiente, textos alternativos en las imágenes y respeto del tamaño de letra del sistema.


SEGURIDAD Y PRIVACIDAD

- Toda la comunicación va por HTTPS.
- La API usa consultas preparadas, valida todos los datos que recibe y exige el token de sesión en las llamadas privadas.
- Los códigos de acceso y los tokens se guardan con hash y caducan.
- La base de datos solo guarda los datos descritos en el apartado 3.1, y borrar una cuenta elimina todos sus datos.
- Reviso la API con la lista OWASP Top 10.


RENDIMIENTO Y COMPATIBILIDAD

- La app de Android abre en menos de 2 segundos en mi celular de pruebas.
- La app funciona en Android 7.0 o superior, y la web en las versiones actuales de Chrome, Firefox, Edge y Safari.


CALIDAD DEL CÓDIGO Y MANTENIMIENTO

- El código sigue la arquitectura por capas y las convenciones de Kotlin, y Android Studio no muestra errores de análisis (lint) al compilar.
- El contenido está separado del código: agregar una unidad no exige cambiar el código.
- Todo el código está en Git, con commits pequeños y mensajes que explican el cambio.


DOCUMENTACIÓN

- El repositorio tiene un archivo README que explica qué es Freenglish, cómo instalarlo y cómo ejecutarlo.
- La API tiene documentado cada endpoint.
- La memoria refleja lo que realmente se hizo, incluidas las incidencias y los cambios.


COSTO

- El costo de funcionamiento se mantiene en 0 € al mes durante el proyecto.
