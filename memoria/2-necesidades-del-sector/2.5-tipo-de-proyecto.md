# 2.5. Tipo de proyecto requerido para responder a las demandas previstas

## Preguntas que determinan el tipo de proyecto

| Pregunta | Respuesta para Freenglish | Motivo (necesidad del apartado 2.3) |
|---|---|---|
| ¿Debe funcionar desde un navegador? | **Sí** | Acceso inmediato, sin instalar nada, desde cualquier ordenador (necesidades 1 y 3) |
| ¿Debe funcionar en varios dispositivos? | **Sí, sobre todo en el móvil** | El público estudia en ratos libres, desde el móvil (necesidad 5) |
| ¿Requiere instalación? | **Opcional** | Se puede usar en el navegador o instalar como app para tenerla a mano y usarla sin conexión |
| ¿Necesita almacenar datos? | **Sí** | Hay que guardar el progreso, los fallos y el calendario de repaso de cada alumno (necesidad 4) |
| ¿Habrá distintos tipos de usuario? | **Sí, dos** | **Visitante:** puede hacer la prueba de nivel y la primera unidad sin registrarse, para probar el curso sin barreras. **Alumno registrado:** cuenta gratuita con correo electrónico verificado y nombre de usuario; su progreso se guarda en el servidor y no se pierde |
| ¿Necesita un servidor? | **Sí, uno pequeño** | Para las cuentas, para guardar y sincronizar el progreso de cada alumno y para recoger estadísticas anónimas. Las lecciones, en cambio, se sirven como archivos estáticos y funcionan sin conexión |
| ¿Debe integrarse con otros sistemas? | **Con las capacidades del dispositivo** | Síntesis de voz del sistema y almacenamiento local. No depende de servicios de pago |

## Alternativas valoradas

| Tipo de proyecto | Ventajas | Inconvenientes | ¿Se elige? |
|---|---|---|---|
| Aplicación web clásica (todo en el servidor) | Una sola versión para todos | Sin conexión no funciona; el servidor tiene que estar siempre disponible y cuesta dinero mantenerlo | No |
| Solo aplicación móvil nativa | La mejor integración con el móvil | Deja fuera a quien no tiene Android o quiere estudiar en el ordenador | No |
| Aplicación de escritorio | Funciona sin conexión | No llega al móvil, que es donde estudia el público objetivo | No |
| **Aplicación multiplataforma: web progresiva (PWA) + app Android + API ligera** | Llega al navegador y al móvil, funciona sin conexión y el coste de mantenimiento es casi nulo | Hay que mantener dos clientes (web y Android) o empaquetar la web; más trabajo que una sola plataforma | **Sí** |

## Tipo de proyecto elegido

Freenglish será una **aplicación multiplataforma con arquitectura cliente-servidor ligera**, formada por tres piezas:

1. **Aplicación web progresiva (PWA):** se usa en cualquier navegador y se puede instalar en el móvil o el ordenador. Guarda el progreso en el propio dispositivo y funciona **sin conexión** una vez descargadas las lecciones.
2. **Aplicación Android:** para quien prefiera instalarla desde una tienda de aplicaciones y para aprovechar mejor las funciones del móvil.
3. **API propia y base de datos:** un servicio pequeño que gestiona las **cuentas de los alumnos** (correo verificado y nombre de usuario), **guarda y sincroniza su progreso** entre dispositivos y recibe las **estadísticas anónimas de uso** (por ejemplo, qué ejercicios se fallan más).

El **contenido del curso** (unidades, frases, ejercicios y explicaciones) se guarda como **datos** en archivos estructurados, separados del código. Las dos aplicaciones leen el mismo contenido, de modo que añadir una unidad, un nivel o un idioma no exige reprogramarlas.

**Cómo se guarda el progreso:** cada respuesta se guarda primero **en el dispositivo** y después se envía al servidor. Así, si el alumno estudia sin conexión (en el metro, por ejemplo), no pierde nada: la app sincroniza el progreso cuando vuelve la conexión. Y si cambia de móvil o estudia también en el ordenador, al iniciar sesión recupera su progreso. **Perder el progreso es una de las peores experiencias para quien estudia**, y este diseño lo evita.

## Por qué esta solución y no otra

- **Llega a todo el público** (navegador y móvil) con un solo curso.
- **Funciona sin conexión**, que es clave para estudiar en el transporte o en un descanso.
- **Coste de mantenimiento muy bajo:** la app es estática y se puede alojar gratis. Solo la API necesita un servidor, y guarda muy pocos datos por alumno. Es lo que permite que Freenglish sea gratis para siempre (apartado 2.4).
- **Pide los mínimos datos personales:** solo un correo electrónico (verificado, para poder recuperar la cuenta) y un nombre de usuario, que hace la experiencia más cercana. Y se puede probar el curso antes de registrarse.
- **Encaja con el ciclo de DAM:** combina desarrollo web, móvil, acceso a datos y servicios en red, que son módulos de 2.º curso.

## Decisión pendiente: cómo se construye la app Android

Hay dos formas de hacer la app Android, y la decisión se tomará al redactar el estudio de viabilidad (apartado 3.2):

| | **A) Empaquetar la web (Capacitor)** | **B) App nativa en Kotlin con Jetpack Compose** |
|---|---|---|
| Qué es | La misma PWA dentro de una app Android | Una app Android propia que lee el mismo contenido y usa la misma API |
| Trabajo | Menor: una sola interfaz | Mayor: dos interfaces (web y Android) |
| Relación con el ciclo | Menor | Directa con el módulo de Programación multimedia y dispositivos móviles. Google define Jetpack Compose como su «herramienta moderna recomendada para crear interfaces nativas» en Android |

El criterio será el tiempo disponible y lo que exija el módulo de Programación multimedia y dispositivos móviles, que en octubre de 2026 empieza con Kotlin.
