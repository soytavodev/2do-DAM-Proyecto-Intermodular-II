# 4.8. Documentación necesaria para la ejecución

Estos son los documentos que voy a usar y mantener mientras desarrollo el proyecto. Todos están en el repositorio de la app, salvo la memoria, que tiene su propio repositorio.

- Especificación de requisitos. La lista de requisitos del apartado 2.6 con sus códigos. Me sirve para saber qué falta y para la matriz de trazabilidad.
- Modelo de datos. El diagrama entidad-relación de la base de datos, el script SQL que crea las tablas y el formato JSON del contenido.
- Documentación de la API. Cada endpoint con su método, lo que recibe, lo que devuelve, los errores posibles y un ejemplo.
- Diagramas de arquitectura. Las capas de la app y cómo se comunican la app, la API y la base de datos.
- Planificación. La lista de tareas del apartado 4.1 en el tablero de GitHub Projects, con su estado.
- Plantilla y lista de revisión del contenido. El modelo de unidad y la lista que tiene que pasar cada unidad antes de publicarse.
- Registro de licencias. El origen, el autor y la licencia de cada imagen o frase de terceros.
- Plan de pruebas. Las pruebas de cada requisito, las pruebas unitarias, las pruebas de la API y el guion de las pruebas con usuarios con su cuestionario.
- Registro de incidencias. Los errores y problemas que vayan apareciendo, con el formato del apartado 5.3.
- Registro de cambios. Los cambios respecto a lo planificado, con el formato del apartado 5.5.
- Instrucciones de despliegue. Los pasos para publicar la API y la web y para generar el APK firmado (apartado 4.4).
- README del repositorio. Qué es Freenglish, cómo instalarlo, cómo ejecutarlo y con qué licencias se publica.
- Política de privacidad. El texto que se muestra en la app y en la web.

No quiero repetir la memoria en estos documentos: la memoria explica el proyecto y estos documentos son las herramientas para hacerlo.
